1. 目的与适用范围

这份文档是 macd-momentum 项目在 2026-05-27 时点的目标架构 design doc。它不是阐述当前代码的现状，而是描述下一阶段重构要达到的状态，作为未来 1-2 周（可能更长）的工作参考。

读者: 项目作者 Han，以及任何参与重构 review 的协作者（Claude / Codex）。

这份文档是意见可改的。任何 section 都可以被 codex review 或后续讨论推翻。版本号会随实质变更递增。

2. 触发原因

当前架构在 2026-05 累积了几个具体痛点，重构需要正面回应：

  1. 多 TF look-ahead leak 在 48 小时内出现 3 次: data/raw/*_weekly.json start-of-week stamp、+7 days shift 不严格、pd.resample('W-FRI') label vs 实际 Friday close 早了 4h。每次都被 codex 抓到，每次都改变了下游精度数字（US bottom CI 从 [+0.11, +9.67] 变到 [-0.72, +9.17]）。Engine 自己的 enrich_with_higher_tf 至今仍有同种泄漏。
  2. Walk-forward K=3 在 5 个 cell 上全部失败 R5 标准: in-sample 上看着 CI 显著正的 sweet spot 都是 2024-2026 tail 假象。同一个 feature 轴在 fold1 / fold2 偏好不同 tercile —— 每个 axis 都是 regime predictor，不是 filter。Filter tuning 已经撞天花板。
  3. 脚本之间重复计算: build_analysis_output、analyze_*_pool、walk_forward_*、backtest_cn_b_topology 各自重新跑 MACD + units，5y SPY daily 每次都重算。
  4. 当前 layer 边界模糊: direction_gate（instrument-class aware policy）嵌在 detector 里；swing_labeler（用未来信息的 retrospective label）跟 causal detector 同层；策略层不存在但已经在脑子里规划了 3 种异构策略。

这些问题不是调参问题，而是架构层面的缺失。重构是为了让下一批 detector / strategy 不重复同样错误。

3. In Scope / Out of Scope

In Scope

  • 研究 / 回测 / 优化算法的全套流程
  • 多 TF + 多 instrument class（us_equity / cn_futures）数据接入、缓存、provenance
  • 多种 detector（divergence、exhaustion、未来的 candle-geometry / Brooks 框架）
  • 多种策略（US 期权 5min PA、CN 飞天期权、US 选股扫描），每种自带研究 / 回测 / 验证 pipeline
  • 本机可视化 audit panel
  • 研究产物的可重现性（provenance manifests、artifact ids）

Out of Scope

实盘执行系统 — 完全独立的未来项目

下列内容不在本设计范围内，会作为一个独立项目单独优化：

  • 实盘下单 / 订单路由 / 成交回报
  • 仓位管理 / 风控 / 资金管理
  • 实时异常处理（断网、行情中断、状态恢复、reconnect）
  • 实盘 streaming（websocket、tick-level 处理）
  • 多策略并发执行 / strategy isolation framework
  • 多用户 / 部署 / 云服务 / 推送
  • 移动端 / API gateway

明确划这条线的目的：避免 "为了实盘可能用得着" 而引入大量复杂度。实盘需要的特性，本架构通过明确边界 + envelope contract 而非内部支持来对接 —— 实盘系统作为 envelope 的另一个 consumer 存在。

关键设计选择:

  • 7 层 + 1 横切: 数据 → 派生 → (detectors ⊥ labels ⊥ policies) → regime → strategies → viz。Audit plane 横切所有层。
  • Detectors / Labels / Policies 是严格分离的三块。Labels 可以用未来信息，Detectors 必须 causal，Policies 才是 instrument-class-aware 的。
  • Regime context 是新增层。Walk-forward 失败的直接对策。strategy 可以 condition on regime tag。
  • Audit plane 是横切而非纵向。它记录"在 t 时刻什么数据可见、什么 event fire、strategy 会做什么"，是 backtest 和未来实盘共用的 traceability。
  • Strategy 之间零共享抽象。每个独立目录，只共享 envelope contract。

5. 各层契约

Data Layer L1

职责: 从外部数据源拉取 OHLCV bar 数据，统一 timestamp 语义，缓存，发布 provenance manifest。

核心输出契约: BarFrame，约束为：

  • 必含列: timestamp (tz-aware UTC), open, high, low, close
  • 可选列: volume, open_interest（cn_futures 才有）
  • timestamp 语义: period END（bar 收盘那一刻）。所有 loader 责任内部统一到这一点。
  • 必带 metadata: provider, symbol, level, session_id（exchange calendar version）, last_completed_ts

不做: streaming / websocket / 自动 reconnect / live tick handling。所有 refresh 都是显式 load(symbol, level, as_of=...) 调用。

Derivations L2

职责: 从 BarFrame 派生确定性的 features 和 unit metadata，提供 cache。这一层不包含 alpha，输出是 lens 不是预测。

输入: BarFrame + 计算参数

输出:

  • features: MACD(close), EMA(close, n), volatility, ...
  • units: HeapInfo, CycleInfo, SegmentInfo（继承自现 engine/units/）
  • derived bars: synthesized higher-TF via no-leak resample

缓存: parquet 文件 + JSON manifest。Cache key 是 (symbol, level, last_bar_ts, params_hash, code_version)。

重要: derivations 是对回测/live 都 deterministic 的。同样输入永远同样输出。无副作用、无随机性。

Detectors L3a

职责: 把 derivations 转换成 causal 的离散事件。

核心契约 (codex M1 reconciled):

detector(
    bars: BarFrame,                                # primary TF
    derivations: Derivations,                      # MACD/units already computed
    *,
    cutoff_ts: datetime,
    foreign_views: dict[str, ForeignTFView] = {},  # {level_id: view}
                                                   # e.g. {"1h": view_1h, "W": view_w}
) -> list[Event]

强约束:

  • 每次调用必须传 cutoff_ts（即使是回测全量跑也要传 = 最后一根 bar 的 ts）
  • 所有 cross-TF 数据通过 foreign_views dict 显式注入，detector 内部不再自己 slice foreign bars
  • detector 不知道 instrument_class（那是 policy 的事）
  • detector 不 import labels（labels 用未来信息，detector 不能间接污染）
  • detector 不知道 regime tag（regime 是 policy + strategy 层 condition 用的，不应反过来污染 detector）

当前 module: engine/divergence/detector.py, engine/divergence/exhaustion.py。重构后 direction_gate 移出（到 L3c policy）。

Labels L3b

职责: 给 derivations 加 retrospective 标注（ZigZag swings、forward return outcomes、regime classifications post-hoc...）。允许用未来信息。

用途: ground truth for detector validation、target for ML labeling、recall / precision 分母。

严格隔离:

  • Labels 模块永远不能被 detector / strategy import
  • Labels 永远不能在 live 时 emit（因为定义就是 retrospective）
  • 类型上 SwingLabel 跟 DetectorEvent 是不同 dataclass，不能互相赋值

当前 module: engine/labels/swing_labeler.py。重构后保持位置，加更严格的类型边界。

Policies L3c

职责: 给 detector event 加上 instrument-class-specific 的 PolicyDecision（weight、rule_id、monitor_required、strategy_hints）。

核心契约: apply_policy(event, instrument_class, regime?) → PolicyDecision

当前 module: engine/divergence/downstream_policies.py。重构后接受 regime tag。direction_gate 从 detector 移到这里。

Regime Context L4

职责: 在每个 cutoff_ts 上给出 ex-ante 的 regime tag。这是直接回应 walk-forward 失败的新层。

v0 设计（最简）: 

RegimeContext(
  cutoff_ts: datetime,
  trend_side_weekly: "bullish" | "bearish" | "transition",
  volatility_band: "low" | "mid" | "high",       # 基于 trailing window
  regime_tag: "trend_bull" | "trend_bear" | "range" | "transition",
)

用途:

  • Policy 可以 condition on regime_tag
  • Strategy 可以 condition on regime_tag
  • Walk-forward harness 可以分 regime 重新验证

验证标准: 加入 regime 后，至少一个之前在 walk-forward 失败的 cell 应当在 favorable regime subset 上 2/2 fold 通过 R5。否则 regime layer 自身需要重设计。

Strategies L5

职责: 把 detector events + policy decisions + regime tag 翻译成具体交易决策。

关键设计: 每个 strategy 完全独立目录，零共享父类。共享只是 envelope contract（消费 AnalysisOutput）。

strategies/
  us_options_5min/
    detector_wiring.py     # 该策略用哪些 detector
    rules.py               # 进场 / 出场 / 加仓 规则
    backtest.py            # 该策略的 backtest entry
    walk_forward.py        # 该策略的 walk-forward
    panel.py               # streamlit panel for this strategy
  cn_xiao_options/
    (same structure, completely separate)
  us_equity_scanner/
    (same structure, completely separate)

共享只能来自 detectors / regime / derivations / data layer。如果两个 strategy 出现相同代码，先保留 duplication，等第三个出现时再抽象（rule of three）。

Audit Plane cross-cutting

职责（v1.5 范围）: 横切所有层；记录在 t 时刻 detector 看到了什么数据 + 用了哪些 derivation artifact + 走到了哪条 policy。完整 schema 在 §6.4。

v1.6 计划: strategy 的 trade-intent audit（具体进场/出场决定 + 用到哪些 events + sizing 计算 trace），在 Step 8a strategy 骨架落地后定 schema。本设计 scope 内 不 实现 strategy-intent audit（决策记录 §14.3）。

实现: 每个 detector event 必带 audit 字段（full schema 在 §6.4）。

这是 codex review 提出的关键新概念，是修复 leak 类 bug 的结构性答案：发现可疑结果时回查 audit 一目了然，不用再人肉重建。

Visualization L6

职责: 本机 streamlit，每个 strategy 一个 panel。

最小可用集 (codex 强烈建议从这里起步):

  • 单 symbol 的 audit panel: bars + segments + 触发 events + forward return + artifact id 链接
  • 跨 symbol monitoring: 今天哪些 symbol 在哪些 TF fire 了什么
  • 策略 P&L 模拟: envelope → 简单 execution model → equity curve

不做: 实时蜡烛图（TradingView MCP 已经做得很好）；自定义指标 UI；移动端；推送；多用户。

6. 关键抽象

6.1 ForeignTFView — 解决 leak 类 bug 的核心抽象

当前所有 multi-TF 查询都直接做 foreign_bars[foreign_bars['timestamp'] <= ts]。三次连续 leak 的根源都是这个模式没考虑 bar timestamp 语义。

新 API:

class ForeignTFView:
    """A causal view of foreign-TF bars at a given cutoff_ts.

    Promises:
      - All accessor methods return only data whose period CLOSED at or
        before cutoff_ts (per the exchange-calendar of the underlying
        BarFrame — not just timestamp arithmetic).
      - For period-end-stamped bars (our internal convention) this is
        direct; provider adapters normalize BEFORE the view is built.
      - require_completed=True (default) refuses to admit partial bars.
        Determining "completed" uses the bar's exchange calendar +
        session end time + provider latency hint, NOT just last_ts.
    """

    def __init__(self, bars: BarFrame, level: str, cutoff_ts: datetime,
                 *, require_completed: bool = True): ...

    # Named state_at to make "as-of cutoff" explicit at the call site,
    # even though cutoff is bound at construction (codex M1 naming fix).
    def state_at(self) -> LevelState:
        """Return derived state (trend_side / cycle_state / ...) at cutoff_ts.

        Implementation: backed by DerivedStore + prefix-safe precompute
        (decision §14.1). MACD / EMA / heap / cycle / segment are causal —
        each bar's output depends only on prior bars. So the derivation is
        computed ONCE over the full BarFrame, persisted as parquet, and
        state_at(t) becomes an O(1) lookup of the row at cutoff_ts.

        Non-prefix-stable derivations (rare; explicitly tagged) fall back
        to an LRU cache keyed by (artifact_id, cutoff_ts, params).
        """

    def last_n(self, n: int) -> BarFrame:
        """Last n completed bars at or before cutoff_ts."""

    def at(self, ts: datetime) -> BarRow | None:
        """The bar whose period ENDED at exactly ts, if any."""

强制性: detector / policy / regime context 任何 cross-TF 查询必须通过这个 view 拿。直接 foreign_bars[...] 在 linter 层面禁止（参考 7.2）。

Calendar awareness (codex M2): require_completed 判断不能只看 last_completed_ts。CN 夜盘、美股 early close、DST、CN 春节连休、provider 延迟（polygon 通常落后 close 15-30s）都影响 "is this bar truly closed at cutoff_ts" 的判定。BarFrame 的 calendar_version 字段是必需输入。Calendar 库使用 exchange_calendars（决策 §14.2），CN 期货夜盘按需 patch（patch 内容计入 calendar_version 字符串）。

6.2 BarFrame contract

@dataclass(frozen=True)
class BarFrame:
    df: pd.DataFrame          # cols: timestamp(UTC), open, high, low, close, [volume]
    provider: str             # "polygon" / "qveris" / "tqsdk"
    symbol: str
    level: str                # "D" / "1h" / "15m" / "5m" / "W"
    exchange: str             # "XNYS" / "XSHG" / "XSGE" / ...

    as_of: datetime           # when this snapshot was pulled
    last_completed_ts: datetime
    payload_hash: str         # sha256 of the parquet file

    def __post_init__(self):
        # validate contract: tz-aware UTC, required columns, monotone, etc

    @property
    def manifest(self) -> ProvenanceManifest:
        """Return the JSON manifest describing this BarFrame (codex M1: bars
        must publish manifests too, not just Layer 2+ artifacts)."""

7. 类型层强制约束

7.1 Import direction 规则

关键: detectors 不能 import labels —— 这是 leak 类 bug 在 type 层的预防。

7.2 静态检查（lint rules）

用 ruff 或自写 AST 规则强制：

  1. 禁止 bars[bars['timestamp'] <= cutoff] 模式（detector / policy 层）。必须用 ForeignTFView。
  2. 禁止 labels module 被 detectors / strategies import（除非显式 # type: ignore[label-leak] 并有 PR comment 说明）。
  3. 禁止 pd.resample() 在 derivations 外被直接调用（必须通过 BarFrame 的 resample helper，保证 timestamp 语义）。
  4. 禁止 datetime.now() 在非顶层 entry script 中出现（避免隐式 cutoff_ts）。

7.3 Property-based tests

用 hypothesis 对 ForeignTFView 写性质测试:

  1. For any (bars, cutoff_ts): view.last_n(k)['timestamp'].max() <= cutoff_ts
  2. For any partial last bar in bars: require_completed=True 一定排除它
  3. For any synth resampled higher TF: 同样性质必须 hold
  4. For any 时区组合（UTC / Asia/Shanghai / America/New_York）: cutoff 比较结果一致

8. 迁移路径（10 步）

每步在自身依赖满足后可独立 ship —— 不是无序并行（codex M1 reconciliation）。强制要求：

  • envelope v1.4 contract 不变（除非显式 minor bump）

8.0 每步 Exit Criteria 模板（codex Minor m4）

每个 step 在 PR description 里必须填齐：

  1. Dependencies: 列出依赖的 step 编号（必须全部 merged）
  2. Schema changes: 改了哪些 dataclass / DataFrame 列 / envelope 字段
  3. Expected regression diff: 列哪些 baseline 输出会变；为什么改变是 expected
  4. Allowed regression diff: 列允许 +/- ε 的输出（譬如 numerical CI 第 3 位小数）
  5. New tests required: 列必须新增的 test 文件 / 测试 case
  6. Rollback policy: 这步 ship 后如果发现问题，怎么撤回（revert / 配置开关 / data migration）

10. 一个端到端示例

展示新架构下"在 2026-04-21 这一天，对 SPY 跑 exhaustion detector，看 1h regime context，给 US options 5min strategy 生成入场决策"的完整调用链:

# Layer 1: 数据
spy_d  = data.load("polygon", "SPY", "D",   as_of="2026-04-21T20:00:00Z")
spy_1h = data.load("polygon", "SPY", "1h",  as_of="2026-04-21T20:00:00Z")
spy_w  = data.load("polygon", "SPY", "W",   as_of="2026-04-21T20:00:00Z")
# spy_d 是 BarFrame，自带 provenance manifest

# Layer 2: 派生量（自动 cache）
deriv_d = derivations.compute(spy_d)
# deriv_d.macd, deriv_d.units —— deterministic, parquet-cached

# Layer 3a: causal detector，必须传 cutoff_ts，foreign TF 通过 ForeignTFView
cutoff = spy_d.last_completed_ts
view_w = ForeignTFView(spy_w, "W", cutoff, require_completed=True)
view_1h = ForeignTFView(spy_1h, "1h", cutoff, require_completed=True)

events = detectors.exhaustion(
    bars=spy_d, derivations=deriv_d,
    cutoff_ts=cutoff,
    foreign_views={"1h": view_1h, "W": view_w},
)

# Layer 4: regime context
regime = regime_context.compute(
    daily=spy_d, weekly_view=view_w, cutoff_ts=cutoff,
)
# regime.tag = "trend_bull"

# Layer 3c: policies
decisions = [policies.apply(ev, instrument_class="us_equity", regime=regime) for ev in events]

# Audit plane: 每个 event 自动带 audit blob
# event.audit = {cutoff_ts, data_visible: {D, 1h, W}, regime_tag, ...}

# Layer 5: strategy（独立目录）
from strategies.us_options_5min import rules
trade_intents = rules.evaluate(events, decisions, regime, bars=spy_d)

# Layer 6: viz
# streamlit panel 读 trade_intents + event.audit + 历史前向收益

注意几点:

  • cutoff_ts 在 detector 调用处必须显式传
  • ForeignTFView 是唯一的 cross-TF 查询通道
  • policies 接受 regime tag（向后兼容: regime=None 时走旧逻辑）
  • strategy 不知道也不关心 detector 怎么计算的，只消费 events

11. 反模式清单

以下行为在 review / lint / 文档讨论中显式拒绝（codex 提的 + 我们补充的）：

  1. greenfield 重写。任何 "重新写一遍" 的提议都要先证明 strangler 路径不行。
  2. 把 Layer 2 当 "圣杯"。Walk-forward 已经证明派生量不是 alpha 源。
  3. mtime-based 缓存失效。必须 hash-based + manifest。
  4. 脚本独立 resample / localize / slice foreign TF。必须走 BarFrame / ForeignTFView。
  5. options / futures / equity scanner 共享父类。零共享抽象，每个策略一个独立目录。
  6. 建 dashboard 在 audit / provenance 之前。先有 traceability，再有可视化。
  7. ship 没有 ex-ante regime gate 的 sweet spot。In-sample CI 显著正不够，必须 walk-forward 2/2 fold 通过。
  8. 默认 grace window 包含部分未来 bar。intraday_grace_minutes=30 这种默认必须被 require_completed=True 取代。
  9. detectors import labels。type 层就要禁止。
  10. detector 嵌入 instrument_class。属于 policy。
  11. 跨 strategy import。strategies/A/ 永远不能 import strategies/B/ 的任何东西。
  12. 把实盘需求引入这套架构。实盘是独立项目，通过 envelope contract 对接。
  13. 给 unused / hypothetical 抽象。出现第三个相似策略再抽象。前两个允许 duplication。
  14. 看过 test fold 结果后再选 "favorable regime"（codex Minor m1）。所有 regime 假设必须 pre-register —— 哪个 cell、什么定义、什么阈值、最小 n —— 在跑 test fold 之前。
  15. 看过结果后再改 R5 阈值 / fold 边界（codex Minor m1）。R5 标准是 n≥15 AND ≥+10pp uplift AND CI 排除 0；fold 边界是 train + test 切片定义。两者一旦定就不能因为结果不好而放松。
  16. 接受 regime subset 后 n < 15（codex Minor m1）。subset 后样本不够就是不够，不要凑数。
  17. 历史 audit blob 不标 retroactive（codex Minor m1）。任何不是 detector 第一次 fire 时生成的 audit，必须带 retroactive=true + confidence=inferred，且不允许在 production / walk-forward 里被消费。
  18. 放任 utils/ 变成隐式跨 strategy 抽象（codex Minor m1）。Strategy 之间共享应该是 zero。utils/ 如果出现就必须是 zero-domain logic（譬如纯数学）。任何包含交易概念的 helper 都是 strategy 抽象漏出。
  19. 改 provider / calendar / adjustment_mode 而不 invalidate manifest（codex Minor m1）。这些是 manifest 的 input 字段，改了就要重生产 artifact。Code 里写 provider="polygon" 改成 "polygon-v2" 之类的字面修改必须触发 cache 失效。

14. 决策记录（codex M2/M3/M5 收口）

v0.2 给用户的 6 个待定项已经收口（2026-05-28）。本节作为决策的 audit trail —— 每条记录 (1) 选了哪个 (2) 理由 (3) 哪些 doc 章节因此被改写。

14.1 — DerivedStore cache 策略 [选 C: Prefix-safe precompute]

决定: MACD / EMA / heaps / cycles / segments 等 causal derivations 一次性算完整 series 存 parquet；state_at(t) 退化为 O(1) array index。少数 non-prefix-stable derivations 显式标 causal=False，走 LRU fallback。

理由: 这些 derivations 在数学上就是 causal（每根 bar 输出只依赖前面 bars）。Cache 命中率 100% by construction，比 LRU 快一档。CI 强制每个 derivation 声明 causal: bool。

影响 sections: §6.1 (ForeignTFView.state_at docstring), §8.1 Step 4 (DerivedStore 实现细节)

14.2 — Exchange calendar 库 [选 A: exchange_calendars]

决定: 使用 exchange_calendars Python lib。CN 期货夜盘按需 patch，patch 内容计入 calendar_version 字段（譬如 "exchange_calendars==4.5.0+cn_night_session"）。

理由: 事实标准，社区维护，版本化清晰。从零写 calendar 库的 5 年维护成本会超过整个架构重构。

影响 sections: §6.1 (Calendar awareness), §8.1 Step 0 (calendar 库引入), §12 (从 open question 移除)

14.3 — Strategy-intent audit timing [选 A: v1.6 minor]

决定: 本设计 (v1.5 envelope) 只实现 event-level audit。Strategy-intent audit (trade decisions / sizing / stop placement) 推迟到 v1.6，在 Step 8a strategy 骨架落地后基于实际需求设计 schema。

理由: 没有 strategy 实例之前设计 strategy schema 是过度抽象。Event audit 解决 leak prevention (urgent)，strategy audit 解决 post-mortem (important 但晚做不致命)。

影响 sections: §5 Audit Plane (文字 narrow 到 event), §6.4 (strategy_trace 字段保留但 v1.5 永远 null)

14.4 — Step 0 / Step 3 BarFrame 拆分 [选 A: shim + full loaders]

决定: Step 0 = BarFrame shim + calendar + 1 reference loader（polygon daily，2-3 天）。Step 3 = 全部 loaders 迁到 BarFrame（3-5 天）。Step 1 / Step 3 / Step 4 在 Step 0 完成后可并行。

理由: 短依赖树 → review 周期短 → 错位 ship 风险低。Step 0 单独焦点收窄，PR 小好 review。

影响 sections: §8.1 Step 0/1/3 (已在 v0.2 应用), §8.3 Dependency DAG

14.5 — Step 8 strategy 拆分 [选 A: 8a 骨架 + 8b 研究]

决定: Step 8a (5-7 天) 只做 strategy module 骨架 + wiring + 入参契约 + TradeIntent dataclass，无任何交易逻辑。Step 8b（实际策略研究）作为独立工作流，不在本设计 doc scope。

理由: 架构 vs 研究是不同 artifact。架构 freeze 后期望稳定，研究 iterate。混在一起 design doc 永远 freeze 不了。

影响 sections: §8.1 Step 8a / 8b (已在 v0.2 应用), §8.2 总预估

建议第一个 strategy: US options 5min PA。理由：对入场精度要求最高（option premium 损耗对错误信号最敏感），最能 stress-test detector + regime + audit 三层。

14.6 — Regime 研究 pre-registration [选 B: 中级严格度]

决定: 每次 regime 实验前在 doc/regime-preregistration-YYYY-MM-DD.md 冻结 5 项：

  1. Cell 列表: 具体要测哪些（譬如 "bottom + conf=high, bottom + wick=low"）
  2. Regime 定义: formula + 阈值（譬如 regime="trend_bull" iff weekly_dif > 0 AND ATR_percentile < 0.5）
  3. Fold 边界: train/test 切片日期（已在 walk-forward harness 里 frozen）
  4. Bonferroni 校正: 如果同时测 K 个 cell，要求 p < 0.05/K（譬如 K=5 → p < 0.01）
  5. Regime subset 后最小 n ≥ 15: subset 后样本不够算无效，不能凑数

Step 6 PR 必须引用 pre-reg doc 的 git commit hash 作为 input。Hash 引用 = 防止 pre-reg 被偷偷改。如果实验失败，不允许"调整 regime 定义重跑"，必须开新的 pre-reg 文件且显式说明跟前一份的区别。

理由: Codex 给的最重要反馈。Walk-forward 5 cell 全失败说明 detector 容易过拟合；regime layer 不防 cherry-pick 的话会重复同种错误。B 级抓住核心方法论 (fold + multiple-test + min-n) 同时无第三方 audit 流程负担。

影响 sections: §8.1 Step 6 (acceptance 不再是 milestone，独立 pre-reg 流程)
