**范围修正（2026-05-20）**：本项目只做分析与概率估算（见 `project_scope_analysis_only.md`），**不实现具体交易动作**（止损、仓位、合约选择等）。本备忘录改为**use case 启示**保留——它解释了为什么本项目的输出必须是**连续置信度** + **多档信号**，而非单一布尔事件。

**Use case 启示（保留作为设计动机）：**

期权左侧交易场景下，"等大级别走完再确认"这条标的资产时代的稳健原则不成立——下游消费者需要从置信度低档到高档的全过程信号。

> 在期权操作里，大级别虽然没有走完，但是仍然可以结合小级别形成预期，以非常严的止损来左侧交易。

**对本项目（分析层）的设计要求：**

1. **多档置信度输出**：从"远离"到"预警"到"候选"到"确认"全过程连续输出
2. **漂移期数据暴露**：大级别 MACD 未完成 K 线的当前值要可访问，不能只暴露 completed 值
3. **小级别先行信号要独立通道**：不要等大级别确认后才输出，小级别的领先观察要直接给消费者
4. **不输出具体动作建议**：不写"轻仓预探""加仓"等下游策略层语言

**对应宋理论的概念**（保留作为理论参考）：
- 期权左侧 ≈ 宋的"幸运买点"——小级别超跌反弹时下游消费者进场的依据
- 宋"理性买点"对应高置信度档位的输出
- 两者在本项目里都是 **同一连续置信度谱上的不同档位**，不分开建模

**注意**：这条记忆的"操作建议"内容（严止损、轻仓重仓等）属于**下游独立项目**的关切，本项目记忆主要保留**为什么分析层需要这样设计**的动机部分。
