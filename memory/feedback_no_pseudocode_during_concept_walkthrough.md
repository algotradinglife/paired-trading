在与用户走 K 线动能理论的概念分层（Layer 0 → Layer 9）时，**不要输出伪代码或代码示例**——用户要的是**思路探讨和概念澄清**。

**Why:** 用户明确说"暂时不用输出伪代码。我们做思路探讨澄清就好"。代码会喧宾夺主，把对话从"理解概念"拽到"看代码"，干扰节奏。

**How to apply:**
1. 讲概念时聚焦"几何定义、边界条件、判定逻辑、陷阱、不变量"等**思路层面**
2. 涉及计算可以用数学表达式、可以用文字描述算法步骤，但**不写 `def`/`if`/`for`** 之类的代码块
3. 如果某个概念真的离不开数据结构例示，用表格/列表/自然语言描述结构，不写类型签名
4. 后续真到代码落地阶段（用户明示开始写实现），再用代码
5. 这条只针对概念探讨阶段。文档/wiki 页面里的算法描述也按这个口径——少代码、多概念
